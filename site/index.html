Erase a person's data by destroying one key.

aegis-shred gives every user their own encryption key. Shred the key and every copy of their data (database, replicas, backups, exports) becomes unreadable at once.

Read the docs GitHub

Install

pip install aegis-shred        # Python 3.10+, Linux · macOS · Windows
cargo add aegis-shred          # Rust
cargo install aegis-shred-cli  # the `aegis` command

Five lines

from aegis_shred import MasterKey, Vault

vault = Vault.open("keys.db", MasterKey.from_env("AEGIS_MASTER_KEY"), create=True)
blob = vault.seal("user-42", b"alice@example.com", context=b"users.email")
vault.shred("user-42")
vault.unseal(blob, context=b"users.email")   # raises Shredded

What you get

Per-subject keysCreated on first use, wrapped by your master key in a small SQLite keystore.
Tamper-evident blobsAES-256-GCM in authenticated chunks. Edits, reordering, truncation and wrong context all fail.
Instant erasureNo key cache: a shred takes effect in every process on the next call.
Audit trailHash-chained log of key creation, shreds and rotations, without raw user ids.
Backups handledShred journal re-applies erasures to restored keystores; rotation retires old copies.
Open formatByte-level spec with test vectors and an independent Python implementation in CI.

Know the limits

  • A master key stolen before a shred, together with an old keystore copy, can still decrypt.
  • Plaintext your application copied into logs, caches or analytics is out of reach.
  • No independent security audit yet. Read the threat model.
